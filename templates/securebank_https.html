How HTTPS Protects You
🔐
ENCRYPTION
All data is encrypted with AES-256-GCM before leaving your device. Even on a shared Wi-Fi network, nobody can read the content of your traffic.
🪪
AUTHENTICATION
The server presents a digital certificate signed by a trusted Certificate Authority. This proves you're talking to the real server, not an impersonator.
🛡️
INTEGRITY
HTTPS uses Authenticated Encryption (AEAD). If an attacker modifies even one bit in transit, the receiver detects it and discards the packet.
⏩
FORWARD SECRECY
TLS 1.3 uses ephemeral key exchange (ECDHE). Even if the server's private key is stolen later, past sessions cannot be decrypted.

Key Takeaways for Today's Workshop
❌ NEVER use HTTP for login pages
Any credentials submitted over plain HTTP are visible to everyone on the same network. This includes school Wi-Fi, coffee shop Wi-Fi, and any network where someone is running Wireshark.
✅ HTTPS is the minimum baseline
Every website that handles user data must use HTTPS. Free certificates are available from Let's Encrypt. There is no excuse for plain HTTP in production in 2024.
⚠️ HTTPS ≠ safe website
HTTPS protects the connection, not the destination. A phishing site can use HTTPS too. Always verify the domain — the padlock just means the connection is encrypted.
