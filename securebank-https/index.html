HTTP vs HTTPS
Feature HTTP HTTPS
Encryption ✖ None ✔ TLS
Credentials visible ✖ Plaintext ✔ Ciphertext
Wireshark readable ✖ YES ✔ NO
MITM risk ✖ Critical ✔ Prevented
Server auth ✖ None ✔ Certificate
Integrity check ✖ None ✔ MAC/HMAC
What Wireshark Sees
⚠ Port 8080/8081 (HTTP)
📖 Full HTTP headers, URL, method visible
🔓 POST body: username=...&password=... — completely readable
🪪 Session cookies, auth tokens exposed
✔ Port 8443 (HTTPS)
🔐 Only TLS handshake packets (Client Hello, Server Hello, etc.)
🔒 Application data shows as encrypted ciphertext — zero readable content
🛡 Even the URL path is hidden once TLS is established
Key Lesson
HTTPS doesn't just hide data — it creates a cryptographically authenticated, integrity-protected tunnel. Even on a shared WiFi network, an attacker with Wireshark sees only random-looking bytes — no matter what you type into this form.
